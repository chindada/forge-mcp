# forge-mcp — Design

**What:** A clean-room re-architecture of `harness-mcp` into a new repository named `forge-mcp`. Keeps every feature **except Playwright**, decomposes the 2000-line orchestrator god-class into a thin conductor plus small, pure, testable collaborators, and modernizes the public MCP surface.

**Status:** Design complete; intended as the implementation brief for a separate agent building `forge-mcp` from scratch in a new repo. This document is self-contained — the implementing agent should not need the legacy `harness-mcp` source, though it may consult it for reference.

**Audience:** The implementing agent. Precision over prose; every interface sketch is normative.

---

## 1. Purpose & north star

`forge-mcp` is a **stdio MCP server exposing a single tool, `run_forge`**, which orchestrates a **Planner → Generator → Evaluator** loop to autonomously implement a feature described in a design document, writing code into a caller-specified `target_dir`. It is the architecture from Anthropic's *"Harness design for long-running application development"*.

**The single most important design concern is mitigating *context anxiety*** — the tendency of an agent to wrap up work prematurely (declare done, summarize instead of execute, cut corners) as it perceives itself approaching its context-window limit. Over a 10-hour autonomous budget this is fatal. The architecture denies any single agent the chance to feel that pressure through four mechanisms, all of which are **preserved** in this refactor:

1. **Fresh SDK session per phase.** Each of Planner / Generator / Evaluator begins with a clean context. The SDK's own session persists *within* a phase; nothing persists *across* phases except files.
2. **Structured handoff artifacts.** Phases never hand off live context — they hand off files on disk (`plan.md`, `contract.md`, `summary.md`, `eval.json`). Each new session reads only the artifacts it needs, never a bloated transcript.
3. **Hard agent boundaries.** Three driver subprocesses isolated by the SDKs; the orchestrator owns durable state so no agent has to.
4. **Honest non-convergence.** The loop is explicitly bounded (`max_iterations`, `max_runtime_minutes`); a cap-hit returns `status="incomplete"` with `unresolved_gaps` populated, removing any incentive to fake completion.

Every structural decision in this document serves that north star. When a boundary choice is non-obvious, the rationale is stated inline (Rule 4, below).

---

## 2. Goals / Non-goals

**Goals**
- Run autonomously to completion (or a clean cap-hit) over multi-hour budgets.
- Same run semantics, error taxonomy, and on-disk forensics as `harness-mcp` — **minus Playwright**.
- A codebase whose units each fit in an agent's working context and are independently testable.
- Modern, idiomatic MCP server surface.

**Non-goals (v1)**
- No crash-resume; a crash leaves forensic state and the next call starts fresh.
- No mid-phase generator checkpointing (the Codex SDK session is the in-phase context vehicle).
- No git mutations on the target, ever (Rule 11).
- No UI/browser verification (Playwright removed).

## 3. Terminology

- **Codex Python SDK** — the `openai-codex` package (`AsyncCodex`/`AsyncThread`); the harness uses the **async** surface only (the sync surface would block the loop).
- **`codex` binary** — the Rust executable the Codex SDK spawns.
- **Claude Agent SDK** — the `claude_agent_sdk` package, which spawns the `claude` Code CLI as a subprocess.
- **Generator** — the Codex-driven phase that edits `target_dir`.
- **Planner / Evaluator** — the Claude-driven phases (planning, auditing, triage, remediation).
- **Run** — one `run_forge` invocation, identified by an 8-hex-char `run_id` (generated by `TargetLock.acquire()`; §6.5).
- **Iteration** — one generate→evaluate cycle inside a run (`iteration-N/`).

The dual-SDK split (Claude for planning/evaluation, Codex for generation) is **intentional and preserved** — it provides model diversity (a different model evaluates than generates) and uses Codex's sandboxed long-autonomous-coding strength for the generator.

## 4. What changes versus `harness-mcp`

This is a refactor, not a behavior change. Three things change:

1. **Decompose** the orchestrator god-class into a thin conductor + focused collaborators (§5, §8–§11).
2. **Remove Playwright** entirely (§15).
3. **Modernize** the public + internal seams to current MCP/Pydantic best practice (§4.1).

Everything else — the §6 error taxonomy, the phase loop, the triage citation rule, the multi-ref git check, the artifact layout, the umask/permissions discipline, the three-section docstring convention — is **preserved**.

### 4.1 Best-practice modernizations (and why)

| Change | Was (`harness-mcp`) | Now (`forge-mcp`) | Why |
|---|---|---|---|
| Tool return | `dict[str, Any]` via `result.model_dump(mode="json")` | `async def run_forge(...) -> RunResult` | FastMCP emits a real `outputSchema` + `structuredContent`; type-safe; no hand-marshal. |
| Cap bounds in schema | `mcp._tool_manager._tools["…"].parameters = …` (private attr) | `Annotated[int, Field(ge=…, le=…, description=…)]` on the params | FastMCP publishes bounds natively from the annotated signature. No private-attribute reach-in. |
| Design-doc xor | runtime `model_validator` (oneOf rejected by Anthropic) | **unchanged** — stays a `model_validator` | Anthropic's API rejects top-level `oneOf`/`allOf`/`anyOf` on tool input schemas. |
| Status sink | `_DeferredStatus` constructed with placeholder + `rebind` after run-dir | `Status` constructed by the orchestrator **after** the run dir exists | Removes a subclass, the `os.devnull` placeholder, and the rebind try/except. |
| Lock ownership | server acquires via `prebuilt_lock`, orchestrator releases (scattered) | `preflight.prepare_run()` acquires + hands a `PreparedRun`; orchestrator owns release | One readable bootstrap function. The acquire/release split is kept *on purpose* (§8.5 cancellation ordering) but documented, not scattered. |
| Input model | `RunHarnessInput` (pydantic) + `RunInputs` (dataclass) | one `RunForgeInput` (pydantic) passed straight to the orchestrator | Removes duplication. |
| Schema-retry | three near-identical `_X_with_retry` methods | one `with_schema_retry()` helper (two call sites — evaluate, triage; the probe-retry goes with Playwright) | DRY. |
| Bug-fix scars | comments referencing legacy "Gap …" tickets (both `Gap A1–A5` and `Gap 1–5` schemes exist) | invariants stated on the owning unit | Code documents *what must hold*, not *which bug taught us*. |
| Orchestrator state | scattered `self._warnings`, `self._state`, … | explicit `RunLedger` + `RunStateMachine` | Data flow is visible and threadable; units are testable. |

```
drivers/_codex  -> models, schemas        # Codex SDK seam

```

**Forbidden edges (load-bearing):**
- `drivers/*` **must not** import `doctor` or `orchestrator/*` (would cycle; drivers receive a `RunContext` and return typed results — Invariant 3).
- Concrete drivers **must not** import `claude_agent_sdk` / `openai_codex` directly — only via the `_claude.ClaudeRunner` / `_codex.CodexRunner` Protocols (the single mocking seam).
- `triage` and `caps` **must not** do I/O (pure functions; unit-testable without disk or SDKs).
- Only `orchestrator/*` writes `state.json` (Invariant 1); drivers never touch it.

### 5.3 Why this decomposition

The orchestrator's *one* job is **sequencing the state machine across phases**. Everything else is a collaborator:
- **Pure policy** (no I/O, trivially testable): `triage`, `caps`, plus the citation/diff helpers.
- **I/O collaborators**: `drivers/*`, `artifacts`, `status`, `state`, `gitguard`.
- **Lifecycle**: `lifecycle.py` owns the gnarly terminal ordering (cancellation/timeout/failure) so `engine.run()` reads as a clean try/except/finally.

This makes the hard-won invariants (the §6 taxonomy, cancellation ordering, the ≥20-char citation rule) testable in isolation instead of buried in a megafunction, and keeps every file inside an agent's working context.

## 6. Public contract: the `run_forge` tool

### 6.1 Signature

```python
@mcp.tool()
async def run_forge(
    target_dir: str,
    design_doc_path: str | None = None,
    design_doc_content: str | None = None,
    max_iterations: Annotated[int, Field(ge=1, le=100)] = 10,
    max_runtime_minutes: Annotated[int, Field(ge=1, le=24 * 60)] = 600,
    *,
    ctx: Context,
) -> RunResult:
    ...
```

- Returns a `RunResult` (typed structured output). FastMCP generates the `outputSchema`.
- `os.umask(0o077)` is the **very first statement** of the tool body (before pydantic validation, before any filesystem touch).
- The body: `RunForgeInput(...)` validate → `config = RunConfig.from_env()` → `prepare_run(inputs, config)` → `Orchestrator(prepared, inputs, config, ctx, drivers).run()` → return.

> **Verification note (implementer):** confirm that `Annotated[int, Field(ge=, le=)]` bounds appear in the generated `inputSchema` for the pinned `mcp` version (documented FastMCP behavior). If a version regresses, customize the schema through a documented public API — never the private `_tool_manager`. Also confirm the generated input **and** output schemas contain no top-level `oneOf`/`allOf`/`anyOf` (Anthropic rejects them); add a test pinning this, as in §18.

### 6.2 `RunForgeInput` (validation model)

```python
class RunForgeInput(BaseModel):
    """Validated arguments for the run_forge tool.

    Design: single source of truth for the tool's argument invariants — the
        design-doc xor (Decision: exactly one of path/content) and the cap
        ranges. The xor cannot be expressed as a JSON-schema oneOf because
        Anthropic rejects top-level combinators on tool input_schema, so it
        lives in a model_validator and is therefore runtime-only.
    Implementation: extra="forbid"; caps bounded with Field(ge=, le=); the
        model_validator rejects when both or neither design-doc field is set.
    Example: RunForgeInput(target_dir="/p", design_doc_path="/d.md").
    """
    model_config = ConfigDict(extra="forbid")
    target_dir: str
    design_doc_path: str | None = None
    design_doc_content: str | None = None
    max_iterations: int = Field(default=10, ge=1, le=100)
    max_runtime_minutes: int = Field(default=600, ge=1, le=24 * 60)

    @model_validator(mode="after")
    def _exactly_one_design_doc(self) -> "RunForgeInput": ...
```

The tool body constructs `RunForgeInput(...)`; a `pydantic.ValidationError` → `McpError(INVALID_PARAMS)`. The same instance is passed to `prepare_run` and the orchestrator (no separate dataclass).

### 6.3 Error taxonomy (preserved from `harness-mcp`)

| Class | When | Surfacing |
|---|---|---|
| **`McpError(INVALID_PARAMS = -32602)`** | Bad inputs, *before* any run dir exists (the design-doc xor; the file/path checks) | raised in the tool body — see ‡ |
| **`McpError(SERVER_ERROR = -32000)`** | Preflight infra failure: lock busy; missing `claude`/`codex`/skill/auth; `<target_dir>/.harness` unwritable | raised in the tool body — see ‡ |
| **`RunResult(status="failed")`** | Run started but cannot finish: SDK crash; schema parse fail after one retry; disk full | **normal tool return** (never raised) |
| **`RunResult(status="incomplete")`** | Ran cleanly but didn't converge: iteration cap or runtime cap | **normal tool return**; `unresolved_gaps` populated |
| **`RunResult(status="completed")`** | Converged (`eval.no_gaps`) | **normal tool return** |

**Bright line:** terminal run states are never raised — they are normal (non-error) tool returns carrying a `RunResult`. Only pre-run failures use `McpError`. A failed *triage* SDK call (two `OutputSchemaError`s) terminates `failed` with `failed_phase="iter_triaging"` — same shape as other per-driver retry boundaries.

> **‡ How a raised `McpError` actually reaches the client (verify + pin).** Under the pinned `mcp` SDK, a FastMCP `@mcp.tool` does **not** translate a body-raised exception into a JSON-RPC *protocol* error response. `Tool.run` catches every exception and re-raises it as a `ToolError`, which the low-level server turns into a **`CallToolResult` with `isError=true`** whose only payload is a text block: `"Error executing tool run_forge: <message>"`. **The numeric JSON-RPC code (`-32602`/`-32000`) and any `ErrorData.data` are NOT transmitted on the wire** — the host sees `isError=true` plus the message text. So `McpError`'s code is an *internal intent marker*, not a client-visible discriminator (this matches legacy `harness-mcp` behavior). Three consequences the implementer MUST honor:
> 1. **Cap-range violations are caught by pydantic — not jsonschema — and before the body runs.** FastMCP registers its tool handler with `validate_input=False`, so it does **not** validate against the advertised `inputSchema`; instead it validates arguments against the pydantic arg-model it derives from the annotated signature (`call_fn_with_arg_validation`). The §6.1 `Annotated[int, Field(ge=, le=)]` bounds are enforced there, so an out-of-range `max_iterations`/`max_runtime_minutes` raises a pydantic `ValidationError` → `ToolError` → `isError` result *before* the body's `RunForgeInput` runs. The `inputSchema` still *advertises* `minimum`/`maximum` to hosts, but is **not** the enforcement path on this SDK. Only the **design-doc xor** (deliberately not in the schema) reaches the body's `RunForgeInput` model_validator and the explicit `McpError`. (`RunForgeInput`'s `extra="forbid"` governs only *direct* construction, e.g. in tests; unknown tool-call arguments are filtered by FastMCP's derived arg-model before the body, not by this `model_config`.)
> 2. **Pin it.** Add a transport-level test (§18) that drives (a) an out-of-range cap, (b) a both/neither design-doc xor violation, and (c) a preflight failure through an in-memory client, asserting the observed shape — `isError=true` + a message substring. It **cannot** assert a `-32602`/`-32000` code (none is transmitted); do not pin one.
> 3. **The return is schema-validated too — twice.** The `-> RunResult` annotation makes FastMCP validate the return value first via pydantic (`output_model.model_validate` inside FastMCP's `convert_result`), then via the low-level server's jsonschema check against the generated `outputSchema`. Either failure becomes an `isError` result (the pydantic one as a `ToolError` → `"Error executing tool …"`; the jsonschema one as `"Output validation error: …"`), **not** the intended `failed` return. An over-length `traceback_truncated` (`max_length=4096`) fails when the tool body **constructs** `RunResult(...)` (full pydantic `__init__` validation) — surfacing as `"Error executing tool …"`; were that bypassed, the low-level jsonschema `maxLength` check would catch it as `"Output validation error: …"`. (`convert_result`'s `model_validate` short-circuits on a `RunResult` *instance* and does not re-enforce `max_length`.) This is exactly why §8.5 truncates the traceback to ≤4096 *before* constructing `RunResult`.
>
> **Design consideration (for the user, not auto-applied):** because the code is not wire-visible, a caller cannot programmatically distinguish *bad-input* from *infra-failure* by code — only by message text. If wire-visible discrimination is wanted, encode a stable token in the message or return a structured error payload; that is an enhancement beyond this behavior-preserving refactor.

### 6.4 Preflight ordering (`prepare_run`)

`prepare_run(inputs: RunForgeInput, config: RunConfig) -> PreparedRun` performs, in order:

0. `os.umask(0o077)` (idempotent re-assert; the tool body set it first).
1. `target_dir`: absolute, exists, is a dir, readable+writable → else `INVALID_PARAMS`.
2. `design_doc_path` (if given): absolute, exists, is a file, readable, non-empty → else `INVALID_PARAMS`. (Inline `design_doc_content` non-empty check too.)
3. `mkdir <target_dir>/.harness` (0o700, explicit chmod) → write `.harness/.gitignore` (`O_EXCL`, content `"*\n"`, never overwrite) → `doctor.check_harness_writable(...)` → else `SERVER_ERROR`.
4. Acquire `TargetLock` on `<target_dir>/.harness/run.lock` → on busy, `SERVER_ERROR`. **Before** the slow env-preflight so a busy target fast-fails without paying the ~30s codex probe.
5. `claude` CLI runnable (falls back to `config.claude_cli_path` / `FORGE_CLAUDE_CLI_PATH` when `claude` is not on `PATH` — §6.5) → `SERVER_ERROR` on FAIL.
6. `codex` binary + SDK import + live model probe (`asyncio.wait_for(..., 30)`) → `SERVER_ERROR`.
7. Required-skills live probe (`superpowers:writing-plans`) with `setting_sources=CLAUDE_SETTING_SOURCES` and JSON-schema output → `SERVER_ERROR` if any missing.
8. Claude auth resolvable → `SERVER_ERROR`.

If any of 5–8 fails **after** the lock is acquired, `prepare_run` **releases the lock** before raising (a doomed environment must not lock out the next run). On success it returns `PreparedRun(harness_dir, lock, run_id, config)` — **lock ownership transfers to the orchestrator**, which owns release in all terminal paths.

```python
@dataclass(frozen=True, slots=True)
class PreparedRun:
    """Result of a successful preflight; the run is cleared to start.

    Design: bundles the post-preflight state the orchestrator needs and
        transfers lock ownership to it. The lock is acquired here (before the
        slow env-probe) but released by the orchestrator so the §8.5
        cancellation ordering ("lock released before final state.json") holds.
    Implementation: frozen/slotted; run_id is taken from the lock payload so
        the lockfile, run dir, state.json, and RunResult all agree.
    Example: PreparedRun(harness_dir=Path("/p/.harness"), lock=lock,
        run_id="abcd1234", config=cfg).
    """
    harness_dir: Path
    lock: TargetLock
    run_id: str
    config: RunConfig
```

> **Doctor reuse:** `forge doctor` runs the *environment subset* of preflight (checks 0, 3, 5, 6, 7, 8 + a disk-space warn). The same check functions back both — single source of truth. The Playwright doctor check is **removed**.

### 6.5 `run_id`, `TargetLock`, and `RunConfig`

**`run_id`** — `secrets.token_hex(4)` (8 lowercase hex, matching the `^[0-9a-f]{8}$` pattern in §7). Generated by `TargetLock.acquire()` and written into the lock payload, so the lockfile, run dir, `state.json`, and `RunResult` all reference the same id. `PreparedRun.run_id` reads it back from the lock (§6.4). (Clean-room choice: forge-mcp mints the id inside `acquire()`; legacy minted it in `server.py` and passed it to the `TargetLock` constructor. Either is fine as long as the lock payload and the run dir agree on the id.)

**`TargetLock`** (`lockfile.py`) — one lock per `target_dir` at `<target_dir>/.harness/run.lock` (Invariant 5), backed by `filelock`. Interface and semantics an implementer needs:
- `acquire() -> None` — generates `run_id`, writes the payload, raises `LockBusy` if a *live* lock is already held.
- `release() -> None` — **idempotent** (safe to call twice): the cancellation path releases early, then the orchestrator's `finally` guards a second release via `ledger.lock_released` (§8.5).
- `run_id: str` — readable after `acquire()`.
- Payload (JSON): `{"pid": int, "run_id": str, "started_at": <iso8601>, "target_dir": str}` (matches legacy; `_is_stale` reads only `pid` + the file mtime, but `target_dir` is retained for forensic self-identification).
- **Stale recovery** (Decision 3): a held lock is steal-able iff its holder process is dead (`psutil.pid_exists(pid)` is `False` — this is what `psutil` is for) **OR** the lockfile mtime is older than the stale threshold.
- **Stale threshold MUST exceed the max runtime.** The lockfile mtime is fixed at `acquire()` (no heartbeat in v1), so the mtime arm effectively means "this run *started* more than the threshold ago." With `max_runtime_minutes` capping at `24*60` = 24h, a threshold at/near 24h risks stealing the lock from a run still within its budget. Set it to **36h** (24h cap + 12h grace) to remove that boundary risk (legacy used 24h; forge-mcp widens it — Rule 4). A periodic mtime heartbeat is the more robust alternative but is out of scope for v1.
- Canonicalization uses `os.path.abspath(target_dir)`, **not** `realpath` — symlinked aliases get distinct locks/roots (intentional; §13).

**`RunConfig`** (`config.py`) — `RunConfig.from_env()` is the single source of environment resolution (keeps `server.py` thin and the resolution testable):

| field | env var | default |
|---|---|---|
| `codex_bin` | `FORGE_CODEX_BIN` | `"codex"` (found on `PATH`) |
| `claude_config_dir` | `CLAUDE_CONFIG_DIR` | `None` (inherit SDK default) |
| `claude_cli_path` | `FORGE_CLAUDE_CLI_PATH` | `None` (use `claude` on `PATH`) |

`forge doctor` prints the resolved `codex_bin`/`claude_config_dir`/`claude_cli_path` (§14). `claude_cli_path` preserves the legacy `HARNESS_CLAUDE_CLI_PATH` escape hatch **and is wired through to the SDK** so it works at runtime, not just at preflight: (1) `doctor.check_claude_cli` / preflight check #5 use it as a fallback (`shutil.which("claude") or claude_cli_path`) so the check passes when `claude` is not on `PATH`; (2) `build_options` (§10.1) forwards it as `ClaudeAgentOptions(cli_path=ctx.claude_cli_path)` when set (the driver reads it off its `RunContext`), so the spawned Claude session actually uses that binary. It is threaded to the Claude call sites via `RunContext.claude_cli_path` (§8.4), alongside `claude_config_dir`. This goes one deliberate step beyond legacy (which consumed the var only in the doctor/preflight check and never threaded it to the SDK) — a genuine runtime hatch, not a preflight-only one.

## 7. Data models (`models.py`, `state.py`)

All pydantic v2. `PlaywrightDecision` is **deleted**.

```python
# --- public result ---------------------------------------------------------

class RunResult(BaseModel):
    status: Literal["completed", "incomplete", "failed"]
    run_id: str = Field(min_length=8, max_length=8, pattern=r"^[0-9a-f]{8}$")
    run_dir: str
    iterations_used: int = Field(ge=0)
    runtime_seconds: int = Field(ge=0)
    completed_phases: list[str] = Field(default_factory=list)     # ["plan","iter-1",...]
    unresolved_gaps: list[EvalGap] = Field(default_factory=list)   # populated when incomplete; best-effort on failed
    design_flaw_gaps: list[DesignFlawGap] = Field(default_factory=list)
    artifacts: ArtifactIndex
    warnings: list[str] = Field(default_factory=list)
    message: str
    # failed-only:
    failed_phase: str | None = None
```

## 8. Run lifecycle

### 8.1 `Orchestrator.run()` (`orchestrator/engine.py`)

The conductor. Construction takes the `PreparedRun`, the `RunForgeInput`, the MCP `ctx`, and the three drivers (DI seam — production wires real drivers, tests wire fakes). Flow:

```
# inputs, config = the validated RunForgeInput + RunConfig (constructor args, see prose); target_dir = abspath(inputs.target_dir)
run_id  = prepared.run_id
run_dir = create_run_dir(prepared.harness_dir, run_id)        # makes inputs/ plan/ too
logger  = build_run_logger(run_id, run_dir)                   # harness.run.<id>, one FileHandler, 0600
status  = Status(run_id, ctx, run_dir / "status.log")         # constructed HERE — no rebind
sm      = RunStateMachine(run_dir / "state.json", initial=RunState(state="init", ...))
ledger  = RunLedger()
status.set_max_iterations(inputs.max_iterations)
await disk_space_warn_if_low(run_dir, status, logger, ledger) # async (emits a live status warning); NOT in preflight (no sink there yet)

deps = PhaseDeps(drivers=..., status=status, logger=logger, run_dir=run_dir,
                 target_dir=target_dir, inputs=inputs, config=config)   # built BEFORE the try so every except handler sees it bound
previous_umask = os.umask(0o077)
try:
    sm.transition("canonicalizing"); canonicalize_design(inputs, run_dir, ledger)   # may raise (empty doc / IO) -> except below
    base_git = capture_state_forensic(target_dir, run_dir)    # baseline; writes inputs/git-state.txt when non-None
    capture_uncommitted_forensic(target_dir, run_dir, ledger)
    await warn_if_missing_target_agents_md(target_dir, ledger, status)

    terminal_status, iters = await asyncio.wait_for(
        run_phases(deps, sm, ledger, base_git=base_git), timeout=inputs.max_runtime_minutes * 60)
    ledger.decided_at = now()
    if terminal_status == "incomplete":                       # iteration cap
        ledger.unresolved_gaps = collect_unresolved_gaps(run_dir)   # latest eval.json — same helper handle_timeout uses
    sm.transition("finalizing"); ... ; sm.transition(terminal_status)
    await emit_terminal_status(status, terminal_status)
    apply_caps_and_overflow(ledger, run_dir, logger)          # BEFORE finally so logger is alive

except TimeoutError:
    terminal_status = await lifecycle.handle_timeout(sm, ledger, deps)   # -> "incomplete"
except asyncio.CancelledError:
    await lifecycle.handle_cancellation(sm, ledger, deps, prepared.lock)  # releases lock, writes failed
    raise
except Exception as exc:
    terminal_status = await lifecycle.handle_failure(exc, sm, ledger, deps)   # -> "failed"
finally:
    if not ledger.lock_released:           # cancellation may release early (§8.5 step 3)
        prepared.lock.release()
    teardown_logger(logger)
    os.umask(previous_umask)

return build_result(run_id=run_id, run_dir=run_dir, status=terminal_status,
                    inputs=inputs, sm=sm, ledger=ledger, started_at=...)
```

**Control-flow invariant:** `deps` is constructed **before** the `try` (all its fields are preflight-available), so the `except` handlers can always reference it. `canonicalize_design`/`capture_*` run *inside* the `try` and **can raise** — an `except` that referenced a name bound mid-`try` would `UnboundLocalError` and mask the real failure, turning the intended `status="failed"` into an `isError` result (§6.3‡). `base_git` is the one value produced inside the `try`; it is threaded to `run_phases(..., base_git=...)` separately (the terminal handlers don't need it).

`runtime_seconds` is computed against `ledger.decided_at` (the moment the orchestrator decided to terminate), **excluding** the cleanup grace — the user's cap is about useful work, not teardown.

`apply_caps_and_overflow(ledger, run_dir, logger)` must run on **every result-producing path** (success inline, and inside `handle_timeout`/`handle_failure`) and always **before** the `finally` tears down the logger — the dropped-warning tee writes to `run.log`, so the logger must still be alive. The cancellation path re-raises `CancelledError` and produces no `RunResult`, so caps do not apply there.

**Helpers referenced in the sketch (so the implementer/auditor isn't guessing):**
- `create_run_dir(harness_dir, run_id)` makes `<run-id>/`, `inputs/`, and `plan/` (0700) — **not** the `iteration-N/` dirs, which are created per-iteration (§9.2 step 1).
- `canonicalize_design(inputs, run_dir, ledger)` resolves `design_doc_path`-or-`design_doc_content` into `inputs/design.md` — the canonical copy every later phase reads. Preflight (§6.4) only *validated* the design inputs; this step *reads/resolves* them. It rejects empty/whitespace content and warns (into `ledger.warnings`) on >1 MB without truncating.
- `capture_state_forensic(target_dir, run_dir)` returns the `gitguard.capture_state` baseline (the multi-ref string used for the per-iteration violation diff) **and** writes it to `inputs/git-state.txt` when non-None — so the §13 artifact exists and `ArtifactIndex.git_state_path` is populated (`build_result` globs for it, §11.5). Returns None when `target_dir` is not a git repo / git is missing — then no file is written and `git_state_path` stays None (matching the legacy behavior).
- `capture_uncommitted_forensic` writes `inputs/git-uncommitted.txt` (setting `ledger.git_uncommitted_path`) **only** when porcelain output is non-empty, and appends a `ledger.warnings` entry (`"target_dir has uncommitted changes at run start; see inputs/git-uncommitted.txt"`) so the caller sees the dirty baseline (legacy parity).
- `warn_if_missing_target_agents_md` is **`async`** (awaited, §8.1): it emits a live `status.update(kind="warning")` **and** appends a non-fatal `ledger.warnings` entry when `target_dir` has neither `AGENTS.md` nor `AGENTS.override.md` (with a CLAUDE.md-specific hint when that file exists). Codex auto-loads `AGENTS.md` from cwd upward, so its absence silently strips project guidance from the Generator.
- `disk_space_warn_if_low` is **`async`** (awaited, §8.1): it emits a live `status.update(kind="warning")` + a non-fatal `ledger.warnings` entry when free space under `run_dir` is below the shared threshold (§14); an actual disk-full *mid-run* surfaces as `status="failed"` from a write `OSError`, not from this probe.
- `emit_terminal_status(status, terminal_status)` issues the single terminal `status.update` for the outcome (a thin wrapper over `Status.update` — §12) and is invoked on **every** terminal path (success inline; inside `handle_timeout`/`handle_failure`). It is **`async`** (it awaits `Status.update`, which fans out to async `ctx.report_progress`/`ctx.info`), so it is **awaited** at every call site; likewise all three terminal handlers (`handle_timeout`, `handle_cancellation`, `handle_failure`) are `async def` and are awaited (they emit terminal status and/or `close_drivers`). Binding any of them without `await` would assign a coroutine to `terminal_status` → a `RunResult` validation failure → `isError` instead of the intended terminal return (§6.3‡).
- **umask ownership:** the `previous_umask = os.umask(0o077)` save/restore here is authoritative. The earlier tool-body and `prepare_run` `os.umask(0o077)` calls are pre-validation guards and are *not* separately restored — leaking the tightened mask across the rest of this single tool call is intended (Invariant 7); restoration to the caller's mask happens once, in this `finally`.

### 8.2 `RunStateMachine` (`orchestrator/statemachine.py`)

```python
class RunStateMachine:
    """Owns RunState and its atomic persistence; the only writer of state.json.

    Design: every transition rewrites state.json atomically so a crash leaves a
        consistent snapshot, and last_phase holds the last NON-terminal phase so
        a later failure records failed_phase correctly (transitioning into
        "failed" must not overwrite the phase that failed). Single-writer
        invariant (Invariant 1) lives here.
    Implementation: transition() validates the new RunState through pydantic,
        writes via write_state, updates `current`, and advances last_phase only
        for non-terminal states. iteration is pinned via **fields.
    Example: sm.transition("iter_generating", iteration=2).
    """
    def __init__(self, state_path: Path, initial: RunState) -> None: ...
    @property
    def current(self) -> RunState: ...
    @property
    def last_phase(self) -> str: ...     # last non-terminal phase
    @property
    def iteration(self) -> int: ...
    def transition(self, new_state: StateLiteral, **fields: Any) -> None: ...
```

`last_phase` advances only for states **not** in `{failed, completed, incomplete, cancelling}` — so when the orchestrator transitions into `failed`, `failed_phase` reads the phase that was actually in progress.

**Persistence semantics (forensics).** `RunState` — the on-disk `state.json` model (§7) — has **no** `last_phase`/`failed_phase` field; `last_phase` is in-memory only. On the *handled* failure/timeout paths, `failed_phase` is sourced from `sm.last_phase` onto `ledger.failed_phase` → `RunResult`. For an *unhandled* crash that leaves no `RunResult`, the forensic signal is `state.json.state` itself: no transition ran, so it retains the last persisted non-terminal phase. An auditor therefore reads the in-progress phase from `state` after a hard crash, and from `RunResult.failed_phase` after a handled failure — `state.json` never carries a `failed_phase` field.

### 8.3 `RunLedger` (`orchestrator/ledger.py`)

```python
@dataclass
class RunLedger:
    """Mutable accumulator threaded through the run; replaces scattered self._x.

    Design: makes the run's growing state explicit and testable — phases append
        gaps/warnings, lifecycle sets the terminal/error fields, result reads it.
        Per-call only (Invariant 6); never shared across runs.
    Implementation: plain dataclass of lists + optional terminal fields; no I/O.
    Example: ledger.warnings.append("low disk space"); ledger.decided_at = now().
    """
    warnings: list[str] = field(default_factory=list)
    completed_phases: list[str] = field(default_factory=list)
    unresolved_gaps: list[EvalGap] = field(default_factory=list)
    design_flaw_gaps: list[DesignFlawGap] = field(default_factory=list)
    decided_at: datetime | None = None
    unresolved_overflow_path: Path | None = None
    design_flaw_overflow_path: Path | None = None
    git_uncommitted_path: Path | None = None
    lock_released: bool = False           # set by handle_cancellation; the finally guards a double release
    failed_phase: str | None = None
    error_class: str | None = None
    error_message: str | None = None
    traceback_truncated: str | None = None
```

**Who sets each field:** `canonicalize_design`/`capture_*`/`warn_*` and the phases append `warnings`; the phases append `completed_phases`; the iteration loop fills `design_flaw_gaps` (step 4). `unresolved_gaps` is **not** filled by the loop — it is collected from the latest `eval.json` via a shared `collect_unresolved_gaps(run_dir)` helper on the two incomplete paths (the engine's iteration-cap branch in §8.1 and `handle_timeout` in §8.5) **and**, best-effort, on the failed path (`handle_failure` in §8.5), so all three report gaps identically. `decided_at` is set at the moment of terminal decision by **all three** result-producing paths (success inline, `handle_timeout`, `handle_failure`). `failed_phase`/`error_class`/`error_message`/`traceback_truncated` are set by `handle_failure`. `lock_released` is set by `handle_cancellation` (so the `finally` skips a double release). The overflow paths are set by `apply_caps_and_overflow`. `iterations_used` is **not** a ledger field; `build_result` derives it uniformly from `sm.iteration` — the count the iteration loop returns on success equals `sm.iteration` (the last `iter_done` transition set it), and `sm.iteration` is also the correct last-completed/in-progress count on the timeout/failure paths. (The loop's returned count is therefore informational; `build_result` reads `sm.iteration`.)

### 8.4 `PhaseDeps` & `RunContext`

`PhaseDeps` (frozen) bundles the collaborators the phases **and** the terminal handlers need (drivers, status, logger, run_dir, target_dir, inputs, config) so signatures stay short. It is built **before** the `try` in `run()` (§8.1) — every field is preflight-available — so the `except` handlers can always reference it. `base_git` is deliberately **not** a `PhaseDeps` field: it is captured inside the `try` (by `capture_state_forensic`, which can fail) and passed to `run_phases(..., base_git=...)` separately; only the iteration loop's git-violation check needs it, never the terminal handlers.

`RunContext` (`runcontext.py`, frozen+slots; module renamed `context.py` → `runcontext.py`) is the per-driver-call struct: `run_dir`, `target_dir | None`, `claude_config_dir | None`, `claude_cli_path | None`, `iteration_n | None`. `claude_cli_path` is the **one field added vs legacy** — it carries `RunConfig.claude_cli_path` to the Claude drivers so `build_options` can forward `ClaudeAgentOptions(cli_path=…)` (§6.5/§10.1); like `claude_config_dir` it is `None` for the Codex generator phase. Per Invariant 3 every driver method takes a `RunContext` as its first positional arg; phase-specific knobs are keyword-only. The orchestrator builds a fresh `RunContext` per driver invocation, populating `claude_config_dir`/`claude_cli_path` from `RunConfig`.

### 8.5 `lifecycle.py` — terminal handling

Three handlers + a shared driver-close helper, extracting the legacy try/except/finally ordering:

- **`close_drivers(drivers, logger, grace=5.0)`** — for each active runner: `await asyncio.wait_for(runner.aclose(), grace)`; on `TimeoutError`, `runner.terminate()`; log per-runner duration; suppress + log any exception so cleanup never masks the outcome. (At most one runner is mid-flight — Invariant 2 — so worst-case grace ≈ 5s.)
- **`handle_cancellation(sm, ledger, deps, lock)`** — the **five-step ordering**, preserved exactly:
  1. `sm.transition("cancelling", reason="client-disconnected", cancelled=True)` (record `failed_phase = sm.last_phase` first).
  2. `await close_drivers(...)`.
  3. `lock.release()`; set `ledger.lock_released = True` (so the `engine.run` `finally` skips a second release).
  4. `sm.transition("failed", reason="client-disconnected", cancelled=True)` — final state written **after** lock release so an observer seeing `failed`/`cancelled=True` knows the lock is free.
  5. caller re-raises `CancelledError`.
- **`handle_timeout(sm, ledger, deps)`** — runtime cap. Set `ledger.decided_at = now()`; transition **directly** to `finalizing` (NOT through `cancelling`), `close_drivers`, set `ledger.unresolved_gaps = collect_unresolved_gaps(run_dir)` (latest `eval.json`, numeric iteration sort → `list[EvalGap]`; the same shared helper the engine's iteration-cap branch uses — §8.3), transition to `incomplete`, apply caps/overflow. (`iterations_used` is read from `sm.iteration` by `build_result`, so the incomplete result reports real progress — §8.3.) The inner `CancelledError` `wait_for` raised is consumed here and never reaches FastMCP.
- **`handle_failure(exc, sm, ledger, deps)`** — set `ledger.decided_at = now()`; capture `failed_phase = sm.last_phase`, `error_class`, `error_message`, and the traceback **truncated to ≤4096 chars** (do this truncation *before* `build_result` constructs `RunResult` — `Field(max_length=4096)` is a hard constructor bound, and a violation would itself surface as an `isError` result, not the intended `failed` return — §6.3‡); set `ledger.unresolved_gaps = collect_unresolved_gaps(run_dir)` (best-effort — a malformed `eval.json` must not mask the original exception; legacy parity, so a crash still surfaces the gaps known before it); transition to `failed`; apply caps/overflow. (`iterations_used` from `sm.iteration` via `build_result` — §8.3.)
- **`collect_unresolved_gaps(run_dir)`** — small `lifecycle.py` helper: reads the latest `iteration-N/eval.json` by **numeric** sort and returns `list[EvalGap]`. The engine imports it from `lifecycle` for the iteration-cap branch (§8.1) — the `engine → lifecycle` edge already exists, so both incomplete paths share one implementation with **no new dependency edge**.

> **Invariant (forensic):** client-disconnect → `cancelling` → `failed`; runtime-cap → `finalizing` → `incomplete`. These two timeout-shaped paths must never be conflated.

## 9. Phases (`orchestrator/phases.py`)

### 9.1 Plan phase

`run_plan_phase(deps, sm, ledger)`:
- `sm.transition("planning")`; status update.
- `RunContext(run_dir=run_dir, claude_config_dir=config.claude_config_dir, claude_cli_path=config.claude_cli_path)` (no target_dir/iteration — the planner predates the loop). Use **keyword** args: the field order is `run_dir, target_dir, claude_config_dir, claude_cli_path, iteration_n` (§8.4), so a positional `RunContext(run_dir, claude_config_dir)` would wrongly bind `claude_config_dir` into the `target_dir` slot.
- `recovery = await deps.drivers.planner.write_plan(ctx)`; if non-None, append to `ledger.warnings` + `status.update(kind="warning")` (off-cwd recovery surfacing — §11.4).
- `sm.transition("planned")`; `ledger.completed_phases.append("plan")`.

### 9.2 Iteration loop

`run_iteration_loop(deps, sm, ledger, base_git) -> (terminal_status, iterations_used)`. Before the loop, read `inputs/design.md` once into `canonical_design_doc` (the canonicalized text, passed to triage in step 4). Then for `n` in `1..max_iterations`:

1. **build contract** — create `iteration-N/` (0700) first (`create_run_dir` made only `inputs/` + `plan/`, §8.1). `n==1`: copy `plan/plan.md` → `iteration-1/contract.md`; `n>1`: the evaluator already wrote `iteration-N/contract.md` via `write_remediation`.
2. `sm.transition("iter_generating", iteration=n)`; **`await generator.implement(ctx, codex_bin=…, status_cb=…)`** (Codex turn; streams high-signal events to `status_cb` with `kind="stream"`). **No Playwright probe, no `mcp_servers`.**
3. `sm.transition("iter_evaluating", iteration=n)`; **`er = await with_schema_retry(lambda r: evaluator.evaluate(ctx, retry=r))`**. **No `playwright_needed` arg.** Writes `eval.json` + `eval.md`.
4. **triage when gaps** — `triage_ran = bool(er.gaps)`; if `triage_ran`: `sm.transition("iter_triaging", ...)`; `triage = await with_schema_retry(lambda r: evaluator.triage_design_flaws(ctx, eval_result=er, retry=r))`; `outcome = classify_gaps(er, triage, canonical_design_doc, n)` (§11.1 — a **pure free function**, not a method on `triage`; it also emits coercion-drift / collision / citation-demotion lines into `outcome.warnings`); append `outcome.warnings` to `ledger.warnings`; extend `ledger.design_flaw_gaps` with `outcome.design_flaws`; `eval_for_loop = er.model_copy(update={"gaps": outcome.code_bug_gaps})`. When `er.gaps` is empty this step is skipped and `eval_for_loop = er`.
5. **git-violation check** (after triage, so the synthetic gap is unreachable to classification): if `base_git` and the post-turn `gitguard.capture_state` differ → write `iteration-N/git-violation.txt`, augment `eval_for_loop` with a high-severity "forbidden git mutation" gap, warn. (§11.3)
6. `sm.transition("iter_done", ...)`; `ledger.completed_phases.append(f"iter-{n}")`.
7. **terminal check** — `effective_no_gaps = (not eval_for_loop.gaps) and (er.no_gaps or triage_ran)` → return `("completed", n)`. (The two-conjunct form preserves the edge case where the SDK returns `no_gaps=False` with an empty gap list — that falls through to the cap, not "completed", because `er.no_gaps` is `False` and `triage_ran` is `False`.) If `n == max_iterations` → return `("incomplete", n)`.
8. **write next contract** — `sm.transition("iter_remediating", ...)` **before** the call (so a post-condition `RuntimeError` is classified `iter_remediating`, not `iter_done`); `recovery = await evaluator.write_remediation(ctx, next_iteration_n=n+1, eval_result=eval_for_loop)`; surface recovery (§11.4).

`run_phases(deps, sm, ledger, base_git)` = `run_plan_phase(deps, sm, ledger)` then `run_iteration_loop(deps, sm, ledger, base_git)` (only the iteration loop needs `base_git`).

> **Excised live phase (audit note).** The legacy orchestrator drives a real `iter_pw_probing` phase *every iteration* — a `_probe_playwright_need_with_retry` call writing `playwright-decision.json`, whose result threads `playwright_needed` into `evaluate`. forge-mcp removes the entire phase: no probe call, no `iter_pw_probing` transition, no `playwright_decisions` accumulation, and the probe-retry is dropped (so only two `with_schema_retry` call sites remain — §11.6). An auditor comparing §9.2 against the legacy orchestrator will find this active phase absent **by design**, not by omission.

The on-disk `eval.json` keeps the **full unfiltered** gap list (plus any violation) for forensics; only the in-memory `eval_for_loop` carries the triage-filtered subset into `write_remediation`.

## 10. Drivers & SDK seams

### 10.1 Claude seam (`drivers/_claude.py`) — kept

Exports the `ClaudeRunner` Protocol (`run`/`aclose`/`terminate`) + `ClaudeRunnerImpl`, plus shared helpers:
- `build_options(...)` — every Claude call site goes through it (`setting_sources`, `permission_mode="bypassPermissions"`, `tools={"type":"preset","preset":"claude_code"}`, optional `output_format`, `add_dirs`, `disallowed_tools`, `mcp_servers`, `run_log_path` → a stderr callback teeing `[claude-stderr]` lines to `run.log`, and **`cli_path`** → forwarded as `ClaudeAgentOptions(cli_path=…)` when set, threading the `FORGE_CLAUDE_CLI_PATH` runtime hatch (§6.5); the Claude drivers pass `ctx.claude_cli_path`). **`mcp_servers` stays a generic param** (the Claude SDK natively accepts the nested-dict shape) but no caller passes Playwright anymore.
- `drain_text(messages)` — joins the canonical assistant answer, **preferring the `StructuredOutput` tool_use channel** (last block wins) over `TextBlock`s. Keep this exactly — `output_format` runs intermittently emit only the structured channel.
- `collect_writes_to_basename(messages, basename)` — for off-cwd-write recovery (§11.4).

### 10.3 The three drivers

- **`PlannerDriver.write_plan(ctx) -> str | None`** — Claude session, `cwd=plan/`, `add_dirs=[inputs/]`, `disallowed_tools=["Edit"]`, system prompt directs the agent to invoke `superpowers:writing-plans` and save `plan.md`. Returns an off-cwd recovery descriptor or None.
- **`GeneratorDriver.implement(ctx, *, codex_bin, status_cb, env=None) -> None`** — one Codex turn; input is `iteration-N/contract.md`; `developer_instructions = generator_system.md` (layer-(a) git-mutation prevention); per-turn `sandbox_policy_for(...)` + `never_approval_mode()`; forwards `turn/started`, `turn/completed`, and `item/started` for `{command_execution, function_call, file_change, web_search}` to `status_cb`; backstops `iteration-N/summary.md` if the agent didn't write one. **No Playwright preflight, no `mcp_servers`, no `PlaywrightMissingError`.**
- **`EvaluatorDriver`**:
  - `evaluate(ctx, *, retry=False) -> EvalResult` — Claude session, `cwd=iteration-N/`, `add_dirs=[target_dir, inputs/]`, `disallowed_tools=["Edit"]`, `output_format=EVAL_RESULT_SCHEMA`; writes `eval.json` + `eval.md`. **No `playwright_needed`/`playwright_mcp_config`, no availability probe.**
  - `triage_design_flaws(ctx, *, eval_result, retry=False) -> TriageResult` — `disallowed_tools=["Edit","Write"]`, `output_format=TRIAGE_RESULT_SCHEMA`; writes `triage.json`.
  - `write_remediation(ctx, *, next_iteration_n, eval_result) -> str | None` — `cwd=iteration-{N+1}/`, invokes `superpowers:writing-plans` to author `contract.md`; off-cwd recovery descriptor or None.
  - **`probe_playwright_need` is deleted.**
- **`_run_and_parse_json`** helper (one parse attempt; `OutputSchemaError` on failure) stays; the **orchestrator** owns the single retry via `with_schema_retry`.

## 11. Cross-cutting policy modules

### 11.1 Triage (`orchestrator/triage.py`) — PURE

```python
@dataclass(frozen=True)
class TriageOutcome:
    design_flaws: list[DesignFlawGap]
    code_bug_gaps: list[EvalGap]
    warnings: list[str]

def classify_gaps(eval_result: EvalResult, triage: TriageResult,
                  canonical_design_doc: str, iteration_n: int) -> TriageOutcome:
    """Pair triages to gaps; promote design-flaws; demote everything else.

    Design: a design-flaw classification is accepted ONLY when every
        cited_sections entry is a >=20-char verbatim (whitespace-canonicalized)
        substring of inputs/design.md — this is the strictness gate against a
        model waving away a real bug as a "design flaw". Title collisions and
        unmatched/uncited rows conservatively demote to code-bug. Pure so it is
        unit-testable without disk or SDKs.
    Implementation: canonicalize design doc once; group eval gaps by title;
        colliding titles -> all code-bug; pair by exact title; validate citations;
        promote survivors to DesignFlawGap; collect one warning per demotion and
        per drift/collision/unmatched row.
    Example: classify_gaps(er, tr, canon, 1) -> TriageOutcome([df], [bug], [...]).
    """
```

Helpers `canonicalize_for_citation(text)` (collapse `\s+` → single space, strip) and `validate_citations(cited, canon)` (every entry ≥20 chars and a substring) live here. The caller reads `inputs/design.md` and passes the text in (keeps the module pure). `classify_gaps` is the **single owner** of coercion-drift surfacing: it reads each `GapTriage._coercion_log` and emits one drift warning per entry into `TriageOutcome.warnings` — the iteration loop does NOT separately read `_coercion_log` (so drift is never double-emitted).

### 11.2 Caps (`orchestrator/caps.py`) — PURE

`GAP_LIST_CAP = 50`, `WARNINGS_CAP = 25`.
- `build_gap_overflow(gaps, *, kind, total) -> str | None` — returns the overflow file **content** (markdown) when `len > cap`, else None.
- `split_warnings(warnings) -> tuple[list[str], list[str]]` — `(kept[:25], dropped[25:])`.

`apply_caps_and_overflow(ledger, run_dir, logger)` (a `lifecycle.py` helper — alongside `collect_unresolved_gaps`; both the engine success path and the lifecycle handlers call it, and `lifecycle` already imports `caps`/`artifacts`/`status`, so no new dependency edge) calls these, writes `unresolved-gaps-overflow.md` / `design-flaw-gaps-overflow.md`, appends truncation warnings, and tees dropped warnings to `run.log` — **while the logger is still alive** (before the `finally`). Lists are sliced to the cap before `build_result`. The overflow file contains **only the entries beyond the cap** (the dropped tail), under a "truncated from N total" header; the list embedded in `RunResult` is the capped head — matching legacy behavior exactly.

### 11.3 gitguard (`gitguard.py`, top-level) — multi-ref check

Moved out of the generator (it's orchestrator policy, not generator behavior). Pure-ish (subprocess only):
- `capture_state(target_dir) -> str | None` — HEAD + `refs/heads` + `refs/tags` + worktrees as one multi-section string; None if not a git repo or git missing (silent-skip).
- `capture_uncommitted(target_dir) -> str | None` — `git status --porcelain` (forensic).
- `diff_state(base, end) -> str` — non-empty report iff any section differs.

On a non-empty diff after a generator turn: write `iteration-N/git-violation.txt`, synthesize a high-severity gap, append a warning. **The harness never runs git mutations** — the *next* iteration's contract instructs the agent to undo it. A violation in the final iteration persists; manual cleanup is documented.

Legacy defines these helpers in `drivers/generator.py` and the orchestrator imports them from there — that `orchestrator → drivers.generator` edge exists *only* to reach them. forge-mcp **deletes that edge**: `gitguard` is imported only by `orchestrator/*`, and `generator.py` neither defines nor re-exports git helpers.

### 11.4 Off-cwd-write recovery

`superpowers:writing-plans` defaults to saving at `docs/superpowers/plans/<date>-<feature>.md`; agents have historically followed that instead of cwd, landing `plan.md`/`contract.md` off-cwd and burning ~10 min before the post-condition fired. Two layers (both preserved):
1. **Prevention** — the OVERRIDE block in `planner_system.md` / `evaluator_remediation.md` forbids absolute paths and the default location.
2. **Recovery** — when cwd's `plan.md`/`contract.md` is missing, the driver buffers the full message stream and rescues the **last non-empty** `Write` tool_use whose basename matches (the agent's intent is in `input.content` regardless of where `file_path` pointed), rewrites it to the correct path, and returns a recovery descriptor `str` (capped via `truncate_for_warning`). The orchestrator surfaces it via `ledger.warnings` + `status.update(kind="warning")`.

### 11.5 Result builder (`orchestrator/result.py`)

`build_result(...) -> RunResult` — assembles `ArtifactIndex` by globbing `run_dir` with **numeric** iteration sort (lexicographic breaks at N≥10), populates failed-only fields when `status=="failed"`, computes `runtime_seconds` from `ledger.decided_at` (fallback `now()`). No SDK calls.

### 11.6 Retry helper (`orchestrator/retry.py`)

```python
async def with_schema_retry(call: Callable[[bool], Awaitable[T]]) -> T:
    """Run an output-schema-bearing driver call with exactly one retry.

    Design: the §6.3 schema-retry policy — the SDK does not retry on schema
        mismatch, so the orchestrator does, once, with the verbatim suffix.
        A second OutputSchemaError propagates (terminal "failed" at that phase).
    Implementation: call(False); on OutputSchemaError, call(True);
        any other exception (and the second OutputSchemaError) propagates.
    Example: er = await with_schema_retry(lambda r: ev.evaluate(ctx, retry=r)).
    """
```

forge-mcp has exactly **two** call sites — `evaluate` and `triage_design_flaws`. (Legacy had three; the Playwright probe-retry is removed.)

## 16. Conventions

- **Rule 21 — three-section docstrings.** Every `def`/`async def` whose body is more than `...`/`pass` carries a docstring containing all three labels, each with ≥5 non-whitespace chars: **`Design:`** (why this exists / the tradeoff), **`Implementation:`** (how it works / key invariants), **`Example:`** (minimal usage). Enforced by `scripts/check_docstrings.py` in CI. Files under any `fixtures/` path are exempt. *(This is the user's "every method's comment should fill with design, implementation, example".)*
- **Rule 11 — no git mutations on the target.** Never `git commit`/branch/tag/push/worktree/rebase/`reset --hard` inside `target_dir`. `gitguard` only *reads* state.
- **Rule 8 — fail fast and loud.** Missing skill/CLI/auth/dir → raise `McpError(SERVER_ERROR)` immediately. No silent fallbacks, no degraded modes.
- **Rule 4 — long-term-correct, leave a one-line comment.** On any non-obvious choice, a one-liner explains why this option (not the easier one) is right.
- **Comments cite this design doc by section** (e.g. `# §8.5 cancellation ordering`), not the legacy `harness-mcp` spec.
- **Strip every legacy citation when porting.** Legacy code is saturated with `spec §N line NNN`, legacy `Decision N` numbers, and dated `2026-05-XX-*.md` references. Do NOT carry any over: re-point load-bearing rationale to the matching forge-mcp section (e.g. legacy "spec §9 line 774 taxonomy" → §6.3; "cancellation §9 lines 821-825" → §8.5; "caps §8" → §11.2). A citation with no forge-mcp analogue is **deleted**, not preserved — a stale `spec §9 line NNN` left in forge-mcp code is itself an audit defect. (forge-mcp comments MAY cite this doc's own §19 decisions — e.g. `# Decision 9 (§19)` — since forge-mcp's decision numbering differs from legacy's; just never carry a *legacy* decision number.)

## 19. Decisions log (forge-mcp)

| # | Decision | Rationale |
|---|---|---|
| 1 | Code target is an explicit `target_dir` MCP param | Composability; no ambiguity over which repo changed. |
| 2 | Caps + honest non-convergence (`max_iterations`, `max_runtime_minutes`); cap-hit → `incomplete` | Removes the incentive to fake completion. |
| 3 | Per-`target_dir` lockfile with stale recovery (pid-dead OR mtime > 36h, deliberately > the 24h max-runtime cap) | The real conflict is two runs editing the same code. |
| 4 | Fresh SDK session per phase; artifacts carry cross-phase context | The context-anxiety north star. |
| 5 | No resume in v1; crash leaves forensic state | Keeps v1 lean. |
| 6 | Single-process async FastMCP orchestrator + three driver seams | SDKs already isolate via subprocess. |
| 7 | `openai-codex` pinned to `@main` (+ committed `uv.lock`) | Pre-release, no PyPI; lockfile gives reproducibility. |
| 8 | Skill availability via live SDK probe with runtime `setting_sources` | Tests the same load path the run will use. |
| 9 | Generator git-mutation prevention: dual-layer (system-prompt + multi-ref post-iteration check); `approval_mode=deny_all`, workspace-write sandbox, `networkAccess=True` | HEAD alone misses branch/tag/worktree creation. |
| 10 | Design-doc xor enforced by `model_validator` (not schema `oneOf`) | Anthropic rejects top-level combinators on tool input schemas. |
| 11 | Progress = monotonic integer, `total=None`, rich message; mirror to NDJSON | Loop length is unknowable; faked % mislead. |
| 12 | Tool returns a typed `RunResult`; terminal states are normal returns, only infra failures raise | Caller can programmatically inspect outcomes. |
| 13 | Orchestrator decomposed into thin conductor + pure policy + lifecycle | Testability; each unit fits in an agent's context. |
| 14 | **No Playwright / no browser verification** | Removed in this refactor (the defining scope cut). |

### Invariants

1. **Single state writer** — only `orchestrator/*` (via `RunStateMachine`) writes `state.json`.
2. **Fresh context per phase** — each driver creates its SDK client per call and tears it down via `async with`, so `CancelledError` always reaches subprocess teardown; at most one driver open at a time.
3. **Driver protocol shape** — every driver method takes a `RunContext` first positional; phase knobs are keyword-only; drivers never mutate orchestrator state.
4. **Append-only artifacts within a phase** — re-running an iteration means a new `run-id`.
5. **Lock identity = `target_dir`** — different targets run freely; same target is rejected.
6. **Per-call orchestrator** — one `Orchestrator` per `run_forge` call; no module-level or class-level mutable state.
7. **umask 0077** — first action of the tool; artifacts default 0600/0700, with explicit chmod against umask drift.
8. **Per-run logger isolation** — each run owns a `harness.run.<run_id>` logger, `propagate=False`, one `FileHandler` on `run.log`, removed on teardown.

## 20. Risks & verification notes for the implementer

1. **Annotated `Field` bounds → `inputSchema`** — confirmed working on the installed `mcp` (1.27.x): the caps surface `minimum`/`maximum` and `-> RunResult` produces an object-root `outputSchema`. Keep the §18 pinning test. If a future pin regresses, customize via a documented public API — never the private `_tool_manager`.
2. **Dropping `_auto_approve_codex_requests`** — safe: the Codex SDK's default approval handler already accepts command/file approvals; only the two MCP-specific methods defaulted to `{}` and are unreachable with no MCP servers (§10.2). Verification reduces to confirming that default for the pinned `openai-codex` commit; no handler reinstatement is expected.
3. **`McpError` wire shape** — the §6.3 taxonomy surfaces as `isError` tool results (text message only — the numeric code is **not** transmitted), not JSON-RPC protocol frames, on the pinned SDK; the §18 transport test pins the real shape.
4. **Cancellation ordering and the triage citation rule are correctness/forensic invariants** — port their behavior exactly even though the code moves modules.
5. **`drain_text` structured-channel preference** and the **`_RunLogTeeingStderr` private-deque monkey-patch** are empirically load-bearing — keep them with their defensive guards.
6. **No top-level schema combinators** and **`type:"object"` output_format roots** — Anthropic API hard-rejects violations; keep the pinning tests.
7. **`claude-agent-sdk` version floor** — the legacy `>=0.0.20` floor was too low: `build_options` (§10.1) requires `setting_sources`, the `tools` preset, and `output_format`. Empirically the earliest PyPI release exposing all three (and accepting the exact `build_options` kwargs) is **0.1.20**, so the floor is `>=0.1.20,<1`. Note PyPI jumps `0.1.81` → `0.2.82` (no `0.2.0`–`0.2.81`), so a `>=0.2.82` floor would have excluded the entire active `0.1.x` line — `>=0.1.20` is the correct minimum-capable floor while the committed `uv.lock` still pins the resolved working version. A consumer that ignores the lock must not be able to resolve an SDK lacking these options.
